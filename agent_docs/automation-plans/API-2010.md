# Automation plan: API-2010

## Status

- Test Case: `API-2010` — Completing a ride twice does not duplicate order history
- Artifact status: `validated`
- Validation: case from `test-cases/test-cases.xlsx`; `fake-api/openapi.yaml` `GET /orders`, `POST /rides` 201, `POST /rides/{rideId}/complete` 200 and 409; current `api-tests` sources; `Routes.kt:198-210` returns 409 `ErrorResponse("Ride is missing or cannot be completed")` when the ride cannot be completed
- Generation gate: generate test code only after every plan claim is validated.

## Test contract

| Item | Decision |
|---|---|
| Objective | A second completion of an already completed ride is rejected and leaves exactly one history entry for that ride |
| Preconditions | Fresh isolated sandbox session reset by `ApiTestCase.resetSandboxStates`; all states disabled; one bearer token from `ApiTestCase.obtainToken` and one `X-Sandbox-Session` for every request; no reset between steps |
| Request | `GET /orders`; `POST /rides` body `{"from":"Oak Avenue","to":"Market Street","rideOptionId":1}`; `POST /rides/{rideId}/complete` twice with the captured id; `GET /orders` |
| Expected result | 200 with the three seeded orders; 201 with positive id, `driver_found`, the submitted route and option id 1; 200 with the captured ride id, `completed` and a new order for the route; 409 with `error` "Ride is missing or cannot be completed"; 200 with exactly `completedOrder` followed by `initialOrders` |
| Contract source | `openapi.yaml` `/orders` get, `/rides` post `201`, `/rides/{rideId}/complete` post `200` and `409` (ErrorResponse) |
| Assigned test | Allure ID `2010`; inventory of `@AllureId` in `api-tests/src` shows 2000-2004, 2006-2009, so 2010 is free |

## Risks and stop conditions

- Risk: a count-only history check could pass with a replaced entry; mitigated by exact ordered collection equality.
- Risk: a reset or a new session between completions would make the 409 meaningless; the test uses one token and the per-test cleanup only.
- Stop when: the ID 2010 becomes occupied, any status or body differs from the case, `fake-api` is unreachable or the run reports zero matching tests.
- Do not compensate with backend edits, weaker assertions, retries or unrelated test changes.
